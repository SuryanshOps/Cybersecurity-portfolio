## Introduction to Cyber Security

Cybersecurity is not just about installing firewalls and running antivirus software; it is a continuous lifecycle of risk management. It is the practice of protecting systems, networks, and programs from digital attacks, unauthorized access, and data exfiltration.

Before diving into offensive hacking techniques (Red Team) or defensive network hardening (Blue Team), every security professional must master the theoretical frameworks that define what it actually means to keep data "secure."

---

## 1. The CIA Triad (The Foundation)

The **CIA Triad** is the most fundamental model in cybersecurity. Every security policy, control, and technology is designed to enforce at least one of these three principles. If any of these three pillars are compromised, the system is no longer secure.

> 
> ![CIA Triad Architecture](./images/cia_triad_diagram.png)

### Confidentiality
**Definition:** Ensuring that sensitive data is accessed only by authorized individuals, processes, or systems. 
*   **The Goal:** Prevent data breaches and unauthorized disclosures.
*   **Common Controls:** Encryption (AES, RSA), Access Control Lists (ACLs), multi-factor authentication (MFA), and data masking.
*   **Example Attack:** A hacker stealing an unencrypted database of user passwords.

### Integrity
**Definition:** Ensuring that data is accurate, trustworthy, and has not been maliciously or accidentally altered during storage or transit.
*   **The Goal:** Prevent unauthorized data modification.
*   **Common Controls:** Hashing algorithms (SHA-256), digital signatures, file integrity monitoring (FIM), and strict version control.
*   **Example Attack:** An attacker intercepting a wire transfer request and changing the destination bank account number before it reaches the bank (Man-in-the-Middle).

### Availability
**Definition:** Ensuring that systems, applications, and data are accessible to authorized users exactly when they need them.
*   **The Goal:** Prevent downtime and disruption of services.
*   **Common Controls:** Redundant hardware (Load Balancers, RAID arrays), Distributed Denial of Service (DDoS) protection, and robust disaster recovery/backup plans.
*   **Example Attack:** A massive DDoS attack that floods a web server with fake traffic, causing it to crash and locking out legitimate customers.

## 2. The AAA Framework (Access Control)

While the CIA Triad defines *what* we are trying to protect, the **AAA Framework** dictates *how* we control who gets to interact with our systems.

> 🖼️ **Insert AAA Framework Diagram Below**
> *(Suggested Image: A flowchart showing a user moving from Login (Authentication) to Role Verification (Authorization) to Log Generation (Accounting)).*
> 
> ![AAA Security Flow](./images/aaa_security_flow.png)

### 1. Authentication (Who are you?)
This is the process of verifying a user's identity. 
*   **Implementation:** It requires the user to provide proof of identity. This is typically categorized into three factors:
    *   *Something you know* (Password, PIN)
    *   *Something you have* (Smartphone authenticator app, YubiKey)
    *   *Something you are* (Biometrics: Fingerprint, FaceID)
*   **Best Practice:** Always enforce Multi-Factor Authentication (MFA), which requires at least two of the above categories.

### 2. Authorization (What are you allowed to do?)
Once a user's identity is verified, the system must determine their permissions.
*   **Implementation:** Applying the **Principle of Least Privilege (PoLP)**. A user should only be given the absolute minimum level of access necessary to perform their specific job functions—nothing more.
*   **Example:** A marketing employee successfully authenticates to the corporate network, but they are *authorized* to view only marketing folders, not the HR payroll database.

### 3. Accounting (What did you do?)
Also known as Auditing. This is the process of tracking user activity and network events to maintain a forensic trail.
*   **Implementation:** System logs, SIEM (Security Information and Event Management) platforms, and session recording.
*   **Example:** If a database is deleted at 3:00 AM, the security team uses accounting logs to determine exactly which user account executed the deletion command.

## 3. Risk Management Vocabulary

To communicate effectively in the industry, you must use precise terminology when describing threats. These terms are often confused by beginners but have strict definitions in the enterprise.

*   **Vulnerability:** A measurable weakness or flaw in a system, software, or process. *(e.g., An unpatched Windows server or a broken door lock).*
*   **Threat:** A potential danger that could exploit a vulnerability to breach security. *(e.g., A ransomware gang or a burglar).*
*   **Risk:** The probability that a threat will actually exploit a vulnerability, combined with the potential business impact. *(Risk = Threat × Vulnerability).*
*   **Exploit:** The actual code, script, or technique used by a threat actor to take advantage of a vulnerability.

## Security Posture Matrix

A quick-reference guide linking the core frameworks to real-world defensive implementations.

| Framework Principle | Defensive Technology | Primary Purpose |
| :--- | :--- | :--- |
| **Confidentiality** | AES-256 Encryption | Renders stolen data unreadable. |
| **Integrity** | SHA-256 Hashing | Proves a file has not been tampered with. |
| **Availability** | Cloudflare DDoS Protection | Keeps web servers online during an attack. |
| **Authentication** | Duo / Microsoft Authenticator | Prevents unauthorized network logins. |
| **Authorization** | Role-Based Access Control (RBAC) | Restricts lateral movement inside the network. |
| **Accounting** | Splunk / Elastic SIEM | Provides an immutable log for incident response. |
