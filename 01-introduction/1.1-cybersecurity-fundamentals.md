# 1.1 The Foundation: Why Cybersecurity is More Than Just "Hacking"

When I first started exploring tech, I had the Hollywood version of cybersecurity in my head: running automated scripts in a dark terminal, finding software bugs, and stopping active network breaches in real-time. 

But as I started digging into how actual enterprise systems are built, my perspective shifted entirely. I realized that cybersecurity isn't just about stopping hackers. **It is the engineering discipline of building resilient systems and managing digital risk.**

Whether you are securing a critical municipal water facility or protecting user session tokens in a web app, every single defensive strategy traces back to a core foundation. Let's break down what that actually looks like.

---

## 🛡️ The Holy Trinity of Security: The CIA Triad

If you spend more than five minutes reading about information security, you will run into the **CIA Triad**. It is the blueprint for evaluating system vulnerabilities. Every security tool you deploy is meant to protect at least one of these three pillars.

### 1. Confidentiality (Keeping Secrets)
Confidentiality is about ensuring that sensitive data is accessible *only* to the people or systems authorized to see it. 
* **How we do it:** We use Advanced Encryption Standard (AES-256) for data sitting in a database, TLS 1.3 for data moving across the internet, and strict Role-Based Access Control (RBAC).
* **When it fails:** Think of an unencrypted AWS S3 bucket that accidentally exposes thousands of private medical records to the public internet.

### 2. Integrity (Trusting the Data)
Integrity guarantees that data hasn't been altered, tampered with, or corrupted.
* **How we do it:** We use cryptographic hash functions (like SHA-256). If a file changes even slightly, the hash changes completely. We also use digital signatures and append-only audit logs.
* **When it fails:** Imagine a Man-in-the-Middle (MitM) attack where a hacker intercepts a $100 bank transfer and changes the payload to $10,000 before it reaches the server.

### 3. Availability (Keeping the Lights On)
A perfectly secure system is useless if legitimate users can't access it. Availability ensures that systems and data remain operational when needed.
* **How we do it:** Distributed load balancers, multi-region cloud deployment, and strict 3-2-1 backup strategies.
* **When it fails:** A massive Distributed Denial of Service (DDoS) botnet floods a university's web server until it completely crashes during finals week.

> **The Engineering Trade-off:** In the real world, you rarely get to max out all three. If you want extreme *Confidentiality* (heavy encryption and multi-factor authentication), you often sacrifice some *Availability* (system speed and user convenience). Security is a constant balancing act.

---

## ⚔️ Flipping the Script: The DAD Triad

To build good defenses, you have to think like an attacker. In threat modeling, we look at the inverse of the CIA Triad, known as the **DAD Triad**:

* **Disclosure:** The attacker breaches *Confidentiality* (e.g., stealing passwords).
* **Alteration:** The attacker breaches *Integrity* (e.g., modifying server logs to hide their tracks).
* **Destruction/Denial:** The attacker breaches *Availability* (e.g., deploying ransomware to lock up a hospital's network).

---

## 🧱 Beyond the Perimeter: Defense in Depth

It used to be that companies built a strong firewall (the perimeter) and assumed everything inside the network was safe. Today, relying on a single line of defense is a recipe for disaster. 

Modern security relies on **Defense in Depth**—building overlapping layers of protection.

1. **The Perimeter:** Firewalls and Edge Routers blocking obvious bad traffic.
2. **The Network:** Internal segmentation (so if a hacker gets in, they are trapped in one area).
3. **The Endpoint:** Antivirus and endpoint detection running on actual laptops and servers.
4. **The Application:** Secure coding practices that block SQL injections.
5. **The Data:** Encrypting the raw data itself.

If a zero-day exploit bypasses the firewall, the endpoint protection catches it. If the endpoint fails, the data is still encrypted and useless to the attacker.
