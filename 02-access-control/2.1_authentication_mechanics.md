## 1. The Death of the Perimeter (Introduction to IAM)

Historically, network security relied on a hardened perimeter (firewalls). If you were inside the building, you were trusted. In modern architectures (Cloud, Remote Work, Zero Trust), **Identity is the new perimeter.** 

Identity and Access Management (IAM) is the overarching framework of policies and technologies ensuring that the *right entities* have access to the *right resources* at the *right time*. 

> **Authentication (AuthN) vs. Authorization (AuthZ)**
> *   **AuthN (Who are you?):** The process of verifying a claimed identity.
> *   **AuthZ (What can you do?):** The process of granting or denying permissions based on that verified identity.

<br>

## 2. The 5 Factors of Authentication

Passwords alone (Single-Factor Authentication) are mathematically and practically broken. Enterprise security mandates **Multi-Factor Authentication (MFA)**, which requires an entity to present at least two distinct categories of evidence.

| Factor Category | Technical Definition | Enterprise Examples |
| :--- | :--- | :--- |
| 🧠 **Knowledge** | *Something you know.* | Passwords, PINs, Security Questions. |
| 📱 **Possession** | *Something you have.* | YubiKey (Hardware Token), RSA SecurID, Authenticator Apps (TOTP - Time-based One-Time Passwords), Smart Cards. |
| 👁️ **Inherence** | *Something you are.* | Biometrics: Fingerprint scanning, Retina/Iris scans, Facial recognition. |
| 📍 **Location** | *Somewhere you are.* | Geofencing (e.g., login automatically denied if the IP address originates outside the organization's host country) or GPS coordinates. |
| ⌨️ **Behavior** | *Something you do.* | Typing cadence (how fast you type), mouse movement patterns, or typical login hours. *(Often used for continuous background authentication).* |

<br>

## 3. Network Authentication Protocols (CCNA / Enterprise Focus)

How do routers, switches, and servers actually process these logins? In an enterprise network, authentication is not handled by the local router; it is forwarded to a centralized security server.

### 🔹 RADIUS (Remote Authentication Dial-In User Service)
The open-standard protocol used widely for network access (like connecting to Enterprise Wi-Fi or a VPN). 
*   **Behavior:** Combines Authentication and Authorization into a single process.
*   **Security:** Only encrypts the password in the access-request packet; the rest of the payload is plaintext.

### 🔹 TACACS+ (Terminal Access Controller Access-Control System Plus)
A Cisco-proprietary protocol used primarily for **Device Administration** (e.g., when a network engineer SSHs into a core router).
*   **Behavior:** Strictly separates Authentication, Authorization, and Accounting (AAA). This allows highly granular control (e.g., verifying a user's identity, then explicitly authorizing them to use the `ping` command but denying the `configure terminal` command).
*   **Security:** Encrypts the *entire* payload of the packet.

### 🔹 IEEE 802.1X (Port-Based Network Access Control)
The gold standard for physical and wireless network security. 
*   **Behavior:** When you plug a laptop into an Ethernet wall jack in a corporate office, the switch port remains functionally dead. 802.1X blocks all traffic until the laptop provides a valid digital certificate or credential to the authentication server. 

### 🔹 Kerberos
The default authentication protocol for Microsoft Active Directory (Windows domains).
*   **Behavior:** It uses a ticketing system. Instead of sending passwords across the network, a central server issues a **Ticket-Granting Ticket (TGT)**. The user presents this ticket to access network file shares and printers cryptographically, preventing eavesdropping.

<br>

## 4. Enterprise Identity Federation & SSO

Managing 50 different passwords for 50 different corporate applications leads to extreme password fatigue. Enterprises solve this via Federation.

*   **Single Sign-On (SSO):** A user logs in exactly *once* to a central Identity Provider (IdP) like Okta or Microsoft Entra ID. The IdP then generates a trusted digital token that seamlessly logs the user into Salesforce, Slack, and AWS for the rest of the session.
*   **SAML 2.0 (Security Assertion Markup Language):** The enterprise standard for SSO. It uses XML-based certificates to securely pass authentication data between the Identity Provider and the Service Provider.
*   **OAuth 2.0 & OIDC:** The modern web standard. Whenever you click *"Log in with Google"* on a third-party website, you are using OAuth to delegate authentication without ever handing that website your actual password.

<br>

## 5. Authentication Attack Vectors

Red Teams and Threat Actors specifically target the authentication phase using the following methodologies:

*   **Brute Force & Dictionary Attacks:** Using automated scripts to guess thousands of passwords against a single account.
*   **Credential Stuffing:** Taking a list of stolen usernames and passwords leaked from one website (e.g., a gaming forum breach) and automatically injecting them into enterprise portals (like Office 365), hoping users reused their passwords.
*   **Pass-the-Hash (PtH):** An advanced attack where the hacker extracts the cryptographically hashed version of a password from a compromised machine's memory and uses the hash itself to authenticate to other servers, completely bypassing the need to know the plaintext password.
