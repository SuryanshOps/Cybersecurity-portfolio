## 1. The OS Attack Surface & Hardening

The Operating System (Windows, Linux, macOS) is the critical bridge between physical hardware and software applications. If an attacker compromises the OS, they own the entire machine. 

Out of the box, default Operating Systems are engineered for *convenience* and *usability*, not security. 

> 🧱 **System Hardening:**  
> The systematic process of reducing an operating system's attack surface. This involves disabling unnecessary services, closing unused ports, enforcing strict file permissions, and implementing memory protection protocols.

<br>

## 2. Privilege Levels: User vs. Root

Modern operating systems utilize strict privilege separation to contain malware and limit human error. The system is conceptually divided into two realms: **Userland** and the **Kernel**.

### 👤 Standard User (Least Privilege)
*   **Access:** Can only modify files within their specific user directory (e.g., `/home/john/` or `C:\Users\John\`). 
*   **Restrictions:** Cannot install system-wide software, modify network configurations, or alter core OS files. 
*   **Security Benefit:** If a Standard User accidentally runs a malware `.exe`, the malware only inherits Standard User permissions. It cannot infect the core OS or other users on the same machine.

### 👑 Root / Administrator (Superuser)
*   **Access:** Omnipotent. Has absolute, unrestricted access to every file, process, and hardware component on the system.
*   **The Danger:** If an attacker compromises the Root account, the machine is completely lost.
*   **Enterprise Rule:** **Never log in directly as Root.** Administrators log in as Standard Users and only elevate their privileges temporarily (using commands like `sudo` in Linux or UAC prompts in Windows) for specific tasks.

<br>

## 3. Basic File Permissions (The Access Matrix)

To enforce user boundaries, the OS assigns strict permissions to every single file and directory. In enterprise environments (servers, cloud infrastructure), Linux is the dominant OS. 

Linux breaks permissions down into three actions and three identities.

### ⚙️ The Action Values
*   📖 **Read (r) = 4:** Permission to view the contents of a file.
*   ✍️ **Write (w) = 2:** Permission to modify or delete the file.
*   🏃 **Execute (x) = 1:** Permission to run the file as a program or script.

### 👥 The Identity Groups
Every file evaluates permissions for three tiers of users (UGO):
1.  **User (Owner):** The person who created the file.
2.  **Group:** Other users assigned to the same department/project group.
3.  **Others (World):** Everyone else on the system.

### 🧮 Understanding the Numbers (Octal Notation)
Network engineers use numbers to quickly assign permissions by adding the values together. 

| Notation | Permission Breakdown | Use Case |
| :---: | :--- | :--- |
| **777** | User: `rwx`, Group: `rwx`, Others: `rwx` | **Extremely Dangerous.** Anyone can read, edit, and run this file. |
| **755** | User: `rwx`, Group: `r-x`, Others: `r-x` | Standard for scripts/programs. Owner can edit; everyone else can only run/read it. |
| **644** | User: `rw-`, Group: `r--`, Others: `r--` | Standard for text files. Owner can edit; everyone else can only read it. |
| **600** | User: `rw-`, Group: `---`, Others: `---` | **Highly Secure.** Only the owner can read/edit. Perfect for private SSH keys. |

## 4. Advanced Memory Protection Theories

If an attacker bypasses file permissions, they will try to inject malicious code directly into the computer's RAM. Modern operating systems deploy deep, kernel-level defenses against this.

### 🔀 ASLR (Address Space Layout Randomization)
*   **The Threat:** Legacy malware used to target specific, predictable locations in RAM where the OS always loaded critical processes. 
*   **The Defense:** ASLR acts like a shell game. Every time the computer boots up, ASLR randomly scrambles the memory locations of OS components. If the malware doesn't know where the target is, its exploit automatically crashes.

### 🛑 DEP / NX Bit (Data Execution Prevention)
*   **The Threat:** Attackers try to insert malicious executable code into areas of memory designated only for passive data (like a buffer overflow attack).
*   **The Defense:** DEP marks specific areas of RAM as **Non-Executable (NX)**. If an attacker successfully injects malware into a data block, the OS will instantly kill the process the second it attempts to execute, preventing the payload from firing.

<br>

## 5. The OS Hardening Baseline

When a security engineer deploys a new server, they apply a baseline checklist to secure it:

1.  🚪 **Disable Default Accounts:** Rename the default `Administrator` account and disable the `Guest` account.
2.  🔌 **Minimize Attack Surface:** Uninstall all unnecessary software (bloatware) and close all unused network ports. A web server only needs Port 80 and 443 open; close everything else.
3.  🛡️ **Host-Based Firewall:** Enable native firewalls (like `iptables`/`UFW` on Linux or Windows Defender Firewall) to block unauthorized incoming connections directly at the OS level.
4.  📝 **Auditing & Logging:** Forward OS event logs (Linux `syslog` or Windows Event Viewer) to a centralized SIEM to monitor for repeated failed logins or unauthorized privilege escalations.
