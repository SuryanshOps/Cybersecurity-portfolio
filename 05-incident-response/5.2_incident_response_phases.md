## 1. What is Incident Response?

An **Incident** is a violation (or imminent threat of violation) of computer security policies, acceptable use policies, or standard security practices. 

When an active breach occurs (e.g., ransomware deployment or data exfiltration), a chaotic scramble will lead to destroyed evidence and prolonged downtime. **Incident Response (IR)** is the pre-engineered, highly structured operational blueprint that a Security Operations Center (SOC) follows to regain control of the environment.

<br>

## 2. The NIST Incident Response Lifecycle (SP 800-61)

The undisputed global standard for managing cyber incidents is the **NIST (National Institute of Standards and Technology) Incident Response Lifecycle**. It consists of four primary operational phases, supported by continuous learning.

## 3. Deep Dive: The 4 NIST Lifecycle Phases

### 🛠️ Phase 1: Preparation
*   **The Goal:** Ensure the organization is fully equipped and trained *before* an attack occurs.
*   **Engineering Actions:** Deploying SIEM monitoring tools, establishing an Incident Response Plan (IRP), conducting tabletop exercises, defining roles (who is the Incident Commander?), and maintaining up-to-date contact directories.
*   *Key Axiom:* You cannot effectively respond to an incident if you are scrambling to write a policy while the network is burning.

### 🔍 Phase 2: Detection and Analysis
*   **The Goal:** Identify that an anomaly has occurred, verify it is a real security incident, and scope the blast radius.
*   **Engineering Actions:** 
    * Alert triage via EDR, IDS, or SIEM tools.
    * Determining *what* happened, *when* it happened, and *how* the attacker got in.
    * Classifying the severity level (e.g., Is this a localized malware infection or a full-scale APT data exfiltration?).

### 🛑 Phase 3: Containment, Eradication, and Recovery
This is the core tactical phase where the Blue Team actively fights back against the threat actor.

*   **1. Containment (Stop the Bleeding):** Preventing the malware or attacker from spreading to other systems.  
    * *Short-term containment:* Isolating the compromised machine from the network (quarantining the endpoint via EDR).  
    * *Long-term containment:* Changing enterprise passwords or blocking malicious IP ranges.
*   **2. Eradication (Remove the Threat):** Finding and eliminating the root cause and all artifacts left behind.  
    * Removing backdoors, deleting malicious registry keys, wiping compromised drives, and patching the vulnerability that allowed entry.
*   **3. Recovery (Restore Operations):** Bringing systems back into production safely.  
    * Restoring clean data from immutable backups, verifying system integrity, and monitoring the network closely for any signs of re-infection.

### 📝 Phase 4: Post-Incident Activity (Lessons Learned)
*   **The Goal:** Ensure the organization never makes the same mistake twice.
*   **Engineering Actions:** Conducting a mandatory **Post-Mortem (Root Cause Analysis)** meeting with stakeholders within a few days of incident closure. 
*   **The Deliverable:** Writing an incident report detailing what failed, updating security policies, improving monitoring rules, and adjusting the enterprise defense posture.
